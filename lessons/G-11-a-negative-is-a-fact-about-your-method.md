# G-11 · A negative result is a fact about your method, not about the world

**"I found nothing" is the most over-trusted result there is.** Before you believe it, prove
your method can find something.

## The positive control

**Run the identical search against something you already know is there.** Same terms, same
filters, same time window, same tool.

If the control comes back empty, your method is broken and the original zero means nothing. If
the control works, the zero is real and you can act on it.

**This takes thirty seconds and it changes the answer often enough to be worth it every time.**

## The four ways a search lies

1. **The term was wrong.** A word you assumed appears, does not. Names, spellings and
   abbreviations differ from what you expect.
2. **The scope was wrong.** You searched a mirror instead of the source, a cached copy instead
   of the live one, one section instead of the whole.
3. **The tool failed silently.** A blocked request, an empty JavaScript shell, a rate limit
   returning an empty list rather than an error. **A page that returns a success code can
   contain nothing**, and some sites serve their "not found" page with a success code.
4. **You searched the wrong property.** You looked for a title where the thing that changed
   was an identifier, or vice versa.

## Go to the authority

When a link is dead or a listing is missing, **go up to the organisation's own index of what
is open.** Their list is authoritative; every copy of it is a snapshot that has already begun
to rot. Identifiers are stable across their site redesigns. Paths are not.
